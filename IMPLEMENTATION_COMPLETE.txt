🚀 5 ENDPOINTS IMPLEMENTED
================================================================================

1. POST /api/auth/login
   Input: {"email": "user@example.com", "password": "secret123"}
   Output: {"access_token": "...", "token_type": "Bearer", "user_id": "...", ...}
   Status: 200 (success), 401 (invalid), 422 (validation)

2. POST /api/auth/register
   Input: {"email": "new@example.com", "password": "...", "password_confirm": "..."}
   Output: {"access_token": "...", "user_id": "...", "email": "...", ...}
   Status: 200 (success), 400 (validation), 409 (duplicate), 422 (format)

3. POST /api/auth/logout
   Headers: Authorization: Bearer <token>
   Output: {"message": "Logout realizado com sucesso"}
   Status: 200 (success), 401 (invalid token)

4. GET /api/auth/me
   Headers: Authorization: Bearer <token>
   Output: {"user": {"id": "...", "email": "...", "is_admin": false}, ...}
   Status: 200 (success), 401 (invalid/missing token)

5. POST /api/auth/verify-token
   Headers: Authorization: Bearer <token>
   Output: {"valid": true, "user_id": "...", "email": "..."}
   Status: 200 (valid), 401 (invalid)

🔐 SECURITY FEATURES
================================================================================

✅ JWT Token Signing
   - Algorithm: HS256 (HMAC-SHA256)
   - Secret: JWT_SECRET_KEY (from .env)
   - Expiration: 24 hours (configurable)

✅ Supabase Authentication
   - Password validation via Supabase Auth
   - No local password hashing (delegated to Supabase)
   - Email uniqueness guaranteed

✅ Authorization Header
   - Format: "Bearer <token>"
   - RFC 6750 compliant
   - Extracted via FastAPI Header dependency

✅ Error Handling
   - Proper HTTP status codes (401, 400, 409, 422)
   - Clear error messages (in Portuguese)
   - No sensitive data in responses

✅ Logging
   - INFO level: successful operations (login, register)
   - WARNING level: failed attempts
   - ERROR level: exceptions + stack traces
   - Emoji indicators for quick scanning
